# 企业微信文档：优先使用圆桥（Dayuan Bridge）

## 适用范围

用户需要查询、阅读、检索、汇总企业微信在线文档、表格、智能表格及附件图片时，优先使用已安装的圆桥，通过现有企微登录态让大圆执行任务。包括 doc.weixin.qq.com 链接以及只给出文档名称的请求。

无需创建机器人、申请新应用权限或提取 Cookie。默认不走浏览器逐屏识别，也不运行历史抓包、调试探针或界面校准脚本。

## 调用顺序

1. 优先使用已注册的 `dayuan-local` MCP：先调用 `dayuan_status`，再用 `dayuan_submit` 提交任务，用 `dayuan_result` 获取结果。参数以当前工具 schema 为准。
2. 当前对话没有暴露 MCP 工具时，直接使用 CLI `dayuan`；若 PATH 中找不到，使用 `$HOME/.local/bin/dayuan`（服务安装版也可使用 `/usr/local/bin/dayuan`）。不要因此要求用户重新安装或重启 Codex。
3. 首先执行 `dayuan status`，确认企微登录、会话与桥接状态。当前客户端的 `--help` 和实际状态是能力依据，不把已生成的安装包当作已安装服务。

常规查询示例：

```sh
dayuan status
dayuan ask '查询“项目问题清单”的最新新增记录，返回记录字段、时间依据、来源链接，并识别全部附件图片；无法读取的附件请逐项说明。只读，不修改文档。' --timeout 600
```

耗时任务用提交与轮询，避免一次命令等待过久：

```sh
dayuan submit '这里填写完整查询任务'
dayuan result <返回的job_id> --wait 20
```

持续查询同一个 job_id，直到取得完成状态及实际答复。超时、运行中、未知状态或轮询错误不代表任务未提交，不要自动重复提交，也不要宣称完成。任务期间不要主动切换大圆会话；会话变化或进程重启后以实际错误与任务状态决定后续步骤。

## 任务与结果要求

- 任务包含用户已经提供的文档名称或链接、筛选条件、所需字段和附件要求，不重复询问已有信息。
- “最新新增”应根据创建时间或可靠新增顺序判断。只有末尾记录时明确说明依据，不能直接认定为最新创建。
- 需要附件图片时明确要求逐张读取并说明失败项。只有大圆返回的图片识别文字时，说明这是大圆的识别结果，不宣称已经取得并直接检查原图。
- 以实际返回内容作答，保留来源、关键字段和未完成事项。不能用任务已接受或状态为完成代替业务结果核实。
- 当前默认只读。用户要求修改时，先核实当前工具是否真正支持该写入行为；未经验证不得承诺或声称修改成功。仍遵守用户原有文档权限。

## 服务未运行时

若返回 `BROKER_UNAVAILABLE`，先根据 `dayuan --help` 确认安装方式。旧版临时桥接需要用户在自己的终端运行：

```sh
dayuan start
```

旧版等待 `DAYUAN_BRIDGE_READY` 后继续原任务。0.2 服务安装版改用 `dayuan service start`，随后重新检查 `dayuan status`，不等待旧版就绪标记。仅在确实遇到此阻碍时请用户配合，不提前要求启动。管理员密码只在用户本机终端输入，不索取密码，不修改 sudoers 或系统保护，也不假设其他终端中的 sudo 授权能被当前执行环境复用。

企微需保持登录并存在可用的大圆会话。若出现其他具体错误，先检查状态与错误信息；需要用户恢复登录或启动服务时再说明最小操作。不要擅自改走需要申请权限的方案。
