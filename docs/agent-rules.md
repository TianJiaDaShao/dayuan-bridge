# 企业微信文档：优先使用圆桥（Dayuan Bridge）

## 适用范围

用户需要查询、阅读、检索、汇总企业微信在线文档、表格、智能表格及附件图片时，优先使用已安装的圆桥，通过现有企微登录态让大圆执行任务。包括 doc.weixin.qq.com 链接以及只给出文档名称的请求。

无需创建机器人、申请新应用权限或提取 Cookie。默认不走浏览器逐屏识别，也不运行历史抓包、调试探针或界面校准脚本。

## 调用顺序

1. 直接执行 CLI `dayuan`；若 PATH 中找不到，使用 `$HOME/.local/bin/dayuan` 或 `/usr/local/bin/dayuan`。不再维护或注册 MCP 接入。
2. 首先执行 `dayuan status`，检查服务。0.2.4 会在提交时自动创建并准备专用大圆会话：若 `service_running=true` 且 `automatic_prepare_on_submit=true`，即使 `ready=false`，仍直接执行一次 `submit` / `ask`。不要要求用户打开大圆、选择历史对话、发送校准消息或运行启动命令。以实际提交错误决定是否需要协助。

常规查询示例：

```sh
dayuan status
dayuan ask '查询“项目问题清单”的最新新增记录，返回记录字段、时间依据、来源链接，并识别全部附件图片；无法读取的附件请逐项说明。只读，不修改文档。' --timeout 600
```

耗时任务用提交与轮询，避免一次命令等待过久：

```sh
dayuan submit '这里填写完整查询任务'
dayuan result <返回的job_id> --wait 20
```

持续查询同一个 job_id，直到取得完成状态及实际答复。0.2.4 使用持久化的消息ID/消息基线和客户端完成状态关联回复；首尾标记只作兼容恢复，不再是唯一依据。缺失首标记的已完成答复可以恢复，不要为此重新提交任务。超时、运行中、未知状态或轮询错误不代表任务未提交，不要自动重复提交，也不要宣称完成。任务绑定桥接后台控制器，前台助理窗口可以关闭或切换。若底层历史会话被删除或客户端重启，以实际错误和任务状态决定恢复步骤。

## 任务与结果要求

- 任务包含用户已经提供的文档名称或链接、筛选条件、所需字段和附件要求，不重复询问已有信息。
- “最新新增”应根据创建时间或可靠新增顺序判断。只有末尾记录时明确说明依据，不能直接认定为最新创建。
- 需要附件图片时明确要求逐张读取并说明失败项。只有大圆返回的图片识别文字时，说明这是大圆的识别结果，不宣称已经取得并直接检查原图。
- 以实际返回内容作答，保留来源、关键字段和未完成事项。不能用任务已接受或状态为完成代替业务结果核实。
- 当前默认只读。用户要求修改时，先核实当前工具是否真正支持该写入行为；未经验证不得承诺或声称修改成功。仍遵守用户原有文档权限。

## 服务未运行时

本机已安装 0.2.4 系统服务版，CLI 指向 `/Library/Application Support/Dayuan Bridge/dayuan-cli`。launchd 已验证启动和异常恢复；已验证大圆窗口关闭且桥接后台对象被清空后，CLI 自动创建后台对象、创建全新的专用大圆会话、等待初始化完成、提交实际文档查询并读取完整结果。后台对象不附着任何窗口，不依赖前台助理会话或已有历史对话。首次新建会话需要等待云端初始化，后续调用复用已解除调试的工作进程缓存。

若返回 `BROKER_UNAVAILABLE`，先检查 `launchctl print system/local.dayuan.bridge` 和 `dayuan --version`。仅在系统服务确实无法自行恢复时，再使用 `dayuan service start` / `dayuan service restart`。需要管理员授权时说明是安装或修复服务，不把每次查询变成人工操作。不要索取密码或修改系统保护。

`ready=false` 表示后台对象可能尚未准备，不代表需要用户操作。先让 `submit` / `ask` 自动准备。`JOB_ALREADY_RUNNING` 时继续轮询已有任务；不自动重复提交。`BACKGROUND_SESSION_NOT_READY` 表示自动建会话/云端初始化未完成，先检查实际错误、登录和云端可用性；不能要求预先创建历史对话，也不能泛化为“请打开助理窗口”。

当前约定：由用户保持企微客户端运行且登录，不实现自动启动企微。CLI 自动新建专用会话，无需历史对话。首次安装/升级系统服务仍需管理员授权；任务消息保留在该专用历史中。登录失效、文档权限不足或云端人工确认不能自动绕过。整机重启验收由用户后续自行完成，不为此主动退出、重启企微或整台 Mac。底层调试调用仍可能短暂停顿企微，不能承诺零卡顿或消除云端耗时。仅在实际遇到无法自行解决的阻碍时说明最小配合，不走创建机器人或申请云端应用权限的方案。
